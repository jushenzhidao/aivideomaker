## 0. 结论（先行）

用**同一批输入**跑两套实现：**11 例中 7 例一致、4 例分歧**。4 例分歧归为 **2 条边界规则**，
另有 **1 条键的存废**与 **1 条槽位词表**差异（后两者不是"规则"问题，但都会实际影响对接）。

**已经一致的（不用再谈）**：精确键压过通配 · `*` 是唯一元字符（`?`/`[]` 字面量）·
大小写敏感 · 分辨率后缀先剥再比 · 表值的值域校验 · 空键/重复键（含大小写变体）拒绝 ·
别名 `upstream_model_map`（两者都写且不同 ⇒ 拒绝）· **未命中 ⇒ 报错、绝不兜底**（错在"哪个
`param`"上两边也一致：调用方的错指向 `model`，配置的错指向 `X-Channel-Options`）。

**分歧**：

| # | 分歧 | aivideomaker | video-adapter |
| --- | --- | --- | --- |
| D1 | 多条通配同时命中 | 取**特异性最长匹配** | **报渠道配置错误** |
| D2 | 通配 vs "名字本身是槽位" | **槽位名优先**（通配不改写指名） | **通配优先**（可强转） |
| D3 | `.model` 钉住键 | 存在（断言 + 表外名字生效） | **已撤除**，遗留即报错 |
| D4 | 槽位词表 | 12 个（站点 11 模型键 + `minimaxH3`） | 8 个（上游 API 槽位），**交集仅 2 个** |

**推荐**：D1 取**特异性**（否则"具体+兜底"无法表达，见 §3.1）；D2 取**职责分离**——
`*` 只做兜底、不覆盖指名槽位，"强制改写"交给 `.model` 并以证据字段留痕（见 §3.2）。
两个推荐都会让 3 条现有门禁用例的期望翻转，所以**必须两边同一轮改**。

## 3. 逐条分析

### 3.1 D1：多条通配同时命中

**事实**：`{"doubao-seedance-*": A, "*": B}` + 官方 ID ⇒ 我 `A`、它报错。
更尖锐的一例：`{"doubao-*": X, "*": X}` + `doubao-x` ⇒ 我 `X`、它**报错** ——
两条通配指向**同一个槽位**、结果毫无歧义，仍然拒。

**它的理由**（`ADR-012`）：被删掉的正则表是"顺序敏感"的，所以歧义一律响亮失败、不排序。
**代价**：`*` 匹配一切 ⇒ `*` 与表里任何其它通配**必然重叠** ⇒ **"具体 + 兜底"这种最自然的
写法直接不可用**（而那正是"官方 ID 多种代次 → 同一槽位 + 其余 → 免费兜底"的写法）。

**我的理由**：确定性排序（先比非通配字符数、再比模式串）已经消除"顺序敏感"——同一份表，
结果与书写顺序无关、可预测，且有门禁用**全排列**钉住这条性质。
**代价**：一处歧义不会报错，而是按可预测的优先级静默择一（但有告警说明命中了哪条模式）。

**选项与建议**：

| 选项 | 结果 | 代价 |
| --- | --- | --- |
| (a) 取特异性（我） | "具体+兜底"可用 | 歧义不报错，靠优先级（有告警） |
| (b) 取报错（它） | 任何重叠都响亮失败 | `*` 与其它通配互斥；"具体+兜底"不可表达 |
| (c) 折中：重叠但**同槽位**放行、异槽位报错 | 修掉"同槽位也报错"的荒谬 | **"具体+兜底"仍不可用** |

**建议 (a)**：判断依据是"具体+兜底"是高频真实配置，而它的收益（可预测）已经由确定性排序拿到。
若你更看重"绝不替配置方排序"，那就得接受"一旦用 `*` 就不能再写别的通配"，并在文档里写死。

### 3.2 D2：通配 vs "名字本身是槽位"

**事实**：`{"*": B}` + 调用方指名 `A`（真槽位）⇒ 我透传 `A`、它改写成 `B`。

**它的理由**：它 2026-09-16 撤掉了 `.model` 钉住键，于是 `{"*": X}` 成了"本渠道只跑 X"的
**唯一**表达手段 ⇒ 必须允许它覆盖指名。
**我的理由**：调用方**指名**一个真槽位时被兜底改写，就是"请求值 ≠ 执行值" —— 最容易被读成
"我买的是 A、跑的是 B"（本项目对此类形状最敏感），而且计费档位跟着变。

**关键洞察**：**两种意图被压进了同一个语法** ——
· "凡是我没列的，都落 X"（**兜底**）
· "这个渠道一律跑 X，无视调用方"（**强制**）

两边各缺一半：它**有强制、没有纯兜底**；我**有兜底、没有强制**
（我的 `.model` 只在表外名字生效，不是全覆盖）。

**选项与建议**：

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| (a) 取它 | 通配优先；撤 `.model` | 指名被改写；"纯兜底"无处表达 |
| (b) 取我 | 槽位名优先 | "强制一档"无处表达（除非新增机制） |
| **(c) 职责分离（推荐）** | `*` 及通配 = **只兜底**，不改写指名槽位；`X-Channel-Options.model` = **强制**（全覆盖）+ 断言 + 证据 `model_source=pinned` / `model_map_pattern` | 两边都要动：它要恢复 `.model`（改强制语义），我要把 `.model` 从"表外生效"改成"全覆盖强制" |

**(c) 为什么值得**：表达力完整、语义无歧义；且与项目自己的原则一致 ——
"知识归控制面、数据面只执行"（渠道显式声明 = 不是我们猜）；两种意图各有专键后，
`{"*": X}` 不再需要在两种解释之间二选一 ⇒ **D2 分歧消失**。

### 3.3 D3：`.model` 钉住键的存废

**事实**：我用（断言 + 表外名字生效）；它 2026-09-16 **撤除**，遗留即 `channel_config_error`
（不静默忽略，理由是"以为它还生效的运维会以为这个渠道只跑某个槽位"）。

⚠️ **这条是决策冲突，不是边界差异**：你最初给我的口径明确要求
`X-Channel-Options.model（钉住槽位）`，我据此实现；撤除是并行会话在同一晚的决定。
两个信号互相矛盾 —— **需要你裁**：

- 裁"保留" ⇒ D2 建议走 (c)（`.model` = 强制，通配只兜底）。
- 裁"撤除" ⇒ D2 只能取 (a)（通配优先），且我这边要删掉 `.model`、对遗留键报错
  （与它逐字一致），并同步改我 13 条接线门禁里的 2 条。

### 3.4 D4：槽位词表（**不是规则差异**）

```
aivideomaker （12）: default, HappyHorse, seedance20, wan27, seedance2, seedance25,
                     kling2_5, kling3, ltx23, veo3Fast, veo31Fast, minimaxH3
video-adapter（ 8）: t2v, i2v, t2v_v3, i2v_v3, minimax, seedance20, wan27, happyhorse
交集        （ 2）: seedance20, wan27
```

**含义**：同一串名字在两层的"能不能透传"不同 —— `t2v` / `minimax` 只在它那边合法；
`seedance25` / `kling3` / `veo31Fast` / `minimaxH3` 只在我这边合法。
级联部署（调用方 → video-adapter → aivideomaker）时**每一跳都要有自己的 map**，
`{"*": ...}` 兜底是实际的粘合剂。

**这不是缺陷**（每层只认自己上游的槽位），但两件事必须写进文档：
① 渠道配置**不可跨层照抄**；② 排查"为什么跑的不是我要的模型"时，第一步是确认**哪一层**做的解析。
