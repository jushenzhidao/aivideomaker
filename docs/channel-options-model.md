# `X-Channel-Options` 的模型键：**两项目共用的一套语义**

> 状态：**aivideomaker 侧已落地**（2026-09-17）。video-adapter 侧由并行会话同步落地中。
> 本文与 video-adapter 的 `docs/decisions/ADR-012-model-name-passthrough.md` **描述同一套键**；
> 改这里必须同步改那边 —— 两处漂移会让"同一个头、两种含义"，而它决定**计费档位**。
>
> 🔴 **先读 §9「两处待裁差异」**：键名、默认透传、未命中 400 三项两边已完全一致；
> 但**通配的**"多命中怎么办"与"通配 vs 名字本身是槽位"这两条，**两个项目当前不一致**，
> 需要拍板后才能算真正统一。

## 1. 键

| 键 | 语义 | 备注 |
| --- | --- | --- |
| `model` | 渠道级**钉住槽位** | 请求名解析不出槽位时以它为准；解析得出**且与它不同** ⇒ 渠道配置错误 |
| `model_map` | 调用方名字 → 上游槽位 的映射表 | **精确键优先；通配键（`*`）按特异性最长匹配** |
| `upstream_model_map` | `model_map` 的**别名** | 两个都写且内容不同 ⇒ 拒绝（自相矛盾的配置不替配置方挑一个） |

**默认 = 上游 model 透传**：一个键都不配时，调用方写的名字**原样当作上游槽位**。
本站（aivideomaker）的"上游槽位"是站点 procedure 名里那一段：`ai.minimaxH3` ⇒ 槽位 `minimaxH3`；
站点把模型编在 **procedure 路径**上，创建请求体里**没有** model 字段。

🔴 **不留任何名字猜测表**。曾经有一张"名字里含 `seedance` 就走 `seedance20`"的正则表，
它把 5 个不同代次的原生 ID 静默压进同一个槽位且**不回告警** ⇒ 真上游实测账单差 **7.3 倍**
（110 vs 15 积分），且落进动态计价槽位后支出上限退化成"事后才知道"。
"哪个名字落哪个槽位"是**控制面知识**，只能由渠道用 `model_map` / `model` 声明。

## 2. 判定顺序（唯一权威表述）

    ① 映射表**精确**键命中              → slot = 表值                source=model_map
    ② 名字本身是**已知上游槽位**（剥后缀后） → slot = 名字（**逐字透传**）  source=passthrough
    ③ 映射表**通配**键命中（特异性最长）   → slot = 表值                source=model_map
    ④ 都没命中、但渠道**钉住**了槽位      → slot = 钉住值              source=pinned
    ⑤ 其余                              → **400**（报文列出已知槽位 + 表里已声明的键 + 怎么改）

- **② 排在 ③ 前面是刻意的**：调用方**指名**了一个真槽位时，不该被一条 `"*"` 兜底改写。
  想"这个渠道一律跑某一档"，用 ④ 钉住（并接受"调用方另有指名 ⇒ 报渠道配置错误"）。
- **⑤ 绝不兜底**（旧的 `return "seedance20"` 兜底就是"写错一个字母就直接付费"的入口）。
  拒绝发生在**任何上游请求之前** ⇒ 不浪费一条带凭据的调用。

## 3. 通配键

```
{"doubao-seedance-*": "seedance20", "*": "minimaxH3"}
```

| 规则 | 取值 | 为什么 |
| --- | --- | --- |
| 语法 | **只支持 `*`**（匹配任意字符，含空），可出现在任意位置；**不做正则** | 一条写错的正则会把所有模型静默指到同一槽位 |
| 匹配方式 | **整串**匹配（不是子串/前缀） | `doubao-*` 不得命中 `x-doubao-1` |
| 多命中 | 取**特异性最高**：先比"模式里非通配字符个数"，再比模式串（字典序） | 结果必须**与书写顺序无关** —— JSON 键顺序不该决定计费档位 |
| 大小写 | 匹配**区分**；但同一模式的**大小写变体视为重复键 ⇒ 拒绝** | 与精确键一致；重复键会被 JSON 静默覆盖 |
| 值域 | 必须是已知上游槽位，否则**拒绝** | 否则等于把 400 推到已经带上凭据的上游请求之后 |

> ⚠️ **与 ADR-012 的关系**：`ADR-012`（2026-09-16）写的是"精确匹配，**无通配**、无最长匹配"，
> 理由是它取代的"顺序敏感的正则"这一整类失败模式。2026-09-17 用户要求**支持通配**（`{"*": ...}`）。
> 两者调和后的边界就是上表四条：**通配是渠道声明的显式数据**（不是代码里的正则表）、
> **确定性排序**（与顺序无关）、**命中必须留痕**（进 `warnings`）、**值域受校验**。
> 换句话说：被禁掉的是"代码里猜名字 + 顺序敏感 + 无告警"，不是"渠道声明一条兜底规则"。

## 4. 拒绝规则（全部发生在任何上游请求之前）

| 情形 | 结果 | `param` 指向 |
| --- | --- | --- |
| 头不是合法 JSON / 不是对象 | 400 | `X-Channel-Options`（渠道配置错误） |
| 表的值不在已知槽位 / 空键空值 / 重复键（含大小写变体） | 400 | `X-Channel-Options` |
| 钉住值不在已知槽位 | 400 | `X-Channel-Options` |
| 钉住值与本次解析结果不同 | 400 | `X-Channel-Options`（**不静默改模型**） |
| 名字解析不出槽位且无钉住 | 400 | `model`（**调用方**的错） |
| 头里出现本层不支持的键 | 放行 + **告警**（点名被忽略的键） | — |

把"渠道配置错误"与"调用方传错"分开报：前者是运维的问题，让调用方在 `model` 上找半天会把排查带偏。

## 5. 证据字段（两边各自的落点）

| 项目 | 字段 | 含义 |
| --- | --- | --- |
| aivideomaker | `effective.model` / `effective.model_source` / `effective.model_verified` | 请求值仍是 `requested.model`（**不被改写**）；source ∈ `model_map`/`passthrough`/`pinned` |
| aivideomaker | span `ark.create.submit` 的 `upstream_slot` / `model_source` / `model_verified` | 事后能复盘"这条任务实际跑了哪个模型" |
| aivideomaker | `web_params.procedure` | 真正打到站点的 procedure（`ai.<槽位>`） |
| video-adapter | `effective.model_map_applied` / `effective.model_requested` | 同上语义（响应体已不含 `model`，这一对是判据） |

解析结论**每次都进 `warnings`**（命中映射、命中通配、用了钉住、槽位未实测）——
静默改模型的账单差异是本项目定义为最贵的一类缺陷。

## 6. 唯一登记在案的差异：槽位值域的"掌握程度"

两边都用"**该层已知的上游槽位清单**"作为值域，但掌握程度不同：

| 项目 | 值域来源 | 对"未实测槽位"的处理 |
| --- | --- | --- |
| video-adapter | 上游（aivideomaker）的槽位清单**已实测** | 表外名字 ⇒ 400 |
| aivideomaker | 站点 11 个模型键（i18n 文案，**已知**）∪ 已实测 procedure 的槽位 | **允许**配置，但标注 `model_verified=false` + 告警 |

aivideomaker 侧之所以"允许但不静默"：站点 11 个模型的 procedure 名**尚未取得**
（现有抓包只是路由级 chunk；`docs/web-reverse/README.md` 的待办）。禁止配置会让映射表在
清单到手之前完全无法配置；而不标注就等于把"推断"当"事实"。⇒ 取"允许 + 留痕"。

### 未验证的那一步（必须知道）

`channel_options.procedure_for_slot()` 现状是 `ai.<槽位>` **按命名形态推断** ——
全站点只实测出 `ai.minimaxH3` 一条生成 procedure。⇒ 映射到非 `minimaxH3` 槽位后，
若 procedure 名不对，表现为**上游 NOT_FOUND**（显式失败、不建任务、不计费）。
拿到清单后：把推断换成**表**，并让表里没有的槽位直接被拒。

## 7. 迁移（旧的"忽略模型名"行为）

本层旧行为是**写死 `ai.minimaxH3`**、任意模型名都通过。要恢复它，二选一：

```jsonc
// ① 钉住（推荐：意图是"这个渠道只跑一档"）
{"model": "minimaxH3"}

// ② 兜底表（意图是"凡是我表外的名字都落这一档"）
{"model_map": {"*": "minimaxH3"}}
```

**注意**：调用方**指名**了另一个真槽位时，`②` **不会**改写它（②优先于③），
此时若同时用了 `①` 钉住 ⇒ 按渠道配置错误报 400。这是刻意的 —— 宁可报错，也不静默换模型。

## 9. ⚠️ 两处待裁差异（**两个项目当前不一致**）

键名（`model` / `model_map` / 别名 `upstream_model_map`）、**默认透传**、**未命中 400**、
值域校验、重复键拒绝、命中留痕 —— 这些两边**完全一致**。下面两条不一致，需拍板：

| # | 议题 | aivideomaker（本文 §3，已实现并有门禁） | video-adapter（其 `ADR-012` 修订 + `video@v1.py`，并行会话落地） |
| --- | --- | --- | --- |
| 1 | **多条通配同时命中** | 取**特异性最高**（非通配字符最多，再比模式串）⇒ 与书写顺序无关 | **报 `channel_config_error`**（不做最长匹配，歧义一律响亮失败） |
| 2 | **通配 vs "名字本身是已知槽位"** | **槽位名优先**（② 在 ③ 前）：调用方指名真槽位时不被兜底改写 | **通配优先**（② 在 ③ 前倒过来）：通配可**强转**模型值，用于承接"本渠道只服务某一档" |

**为什么它们互相冲突而不是各管一段**：`{"doubao-seedance-*": "seedance20", "*": "minimaxH3"}` 这种
"具体 + 兜底"是最自然的写法 ——

- 按 #1「报错」⇒ 这种表**直接不可用**（两条通配重叠）；
  按「特异性」⇒ 可用（`2-0` 落 `seedance20`，其它落 `minimaxH3`）。
- 按 #2「通配优先」⇒ 调用方写 `seedance20` 也会被 `"*"` 改写；
  按「槽位名优先」⇒ 只改表外名字。

**建议（供拍板，非既成事实）**：#1 取**特异性排序**（否则"具体+兜底"表达不出来，而它正是
`{"*": ...}` 的典型用法）、#2 取**通配优先于槽位名**（否则"这个渠道只跑一档"只能靠 `model` 钉住，
而 ADR-012 的钉住是**断言**语义、不是强制语义）。两者都要保留"命中必须留痕"。

拍板后：改本文对应小节 + 两边代码 + 两边门禁（**同一轮改**，别让它继续漂）。
