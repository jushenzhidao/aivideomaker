# 480p / 720p × 1–10 秒 计费枚举（web 内部接口 vs 官方 API）

> 采集时间：2026-09-13 · 适用模型：MiniMax H3（web 端模型名 `default`，API 端 `minimax` / `t2v` / `i2v`）
> 取数口径见文末「证据与局限」，**本表是文档口径的枚举，不是实测账单**。

## 0. 先说两条前置事实

**① 1–4 秒在两条线上都不存在。** H3 的合法时长是 **5–20 秒连续整数**，没有离散档位
（依据：站点 `videoDurationMaxWarnTip` = "Video duration must not exceed {seconds} seconds."，
且 720p 侧 5/6/7/8/9/10/11/14s 逐秒实测全部成功）。

适配层对越界值做**就近吸附**：`1–4s → 5s`。所以下表的 1–4s 行不是"另一个价位"，
而是"会被静默改成 5s"。

**② official 线没有 480p 的 H3 入口。** `minimax` / `t2v` / `i2v` 的 `resolution`
只接受 `720p` / `1080p`。official 侧唯一支持 480 的是 `seedance20`，
而它的定价**按入口、不按输出分辨率**（官方明确要求：一律以报价接口或 `creditsCharged` 为准），
不能按秒线性外推 —— 见 §3。

## 1. 主表：web 内部接口（模型 `default`）

单位：积分。免费窗口以 `paid=false` 为准（**不要看 `credits` 字段，它与 `paid` 反相**）。

| 时长 | 480p（快速） | 720p 快速（turbo） | 720p 质量（base） |
|---|---|---|---|
| 1s | 不存在 → 吸附 5s | 不存在 → 吸附 5s | 不存在 → 吸附 5s |
| 2s | 不存在 → 吸附 5s | 不存在 → 吸附 5s | 不存在 → 吸附 5s |
| 3s | 不存在 → 吸附 5s | 不存在 → 吸附 5s | 不存在 → 吸附 5s |
| 4s | 不存在 → 吸附 5s | 不存在 → 吸附 5s | 不存在 → 吸附 5s |
| 5s | **0**（免费草稿，已实测） | **0**（订阅用户免费，已实测） | 20 |
| 6s | **0** ⚠️ | **0**（已实测） | 24 |
| 7s | **0** ⚠️ | **0**（已实测） | 28 |
| 8s | **0** ⚠️ | **0**（已实测） | 32 |
| 9s | 站点未提供 ⊘ | 27 | 36 |
| 10s | 站点未提供 ⊘ | 30 | 40 |

- **480p 9–10s ⊘**：文案限定"480p 免费生成，**最长 8 秒**"，超出应不被站点接受。
- **⚠️ 480p 6–8s**：文案称免费至 8 秒，但实测样本（`model.listModel`）里 480p 只出现过 5s，
  6/7/8s 的 480p 免费**未逐条实测**。对外宣传口径是"不限量生成 **5 秒** 480p 草稿"。
- **720p 质量（base）**：文案「质量模式每秒增加 1 积分」，且 `base` 档**没有免费窗口**
  （"免费生成暂不支持质量模式"）⇒ 5s 起全程计费。
- 网页定价页另称订阅用户"无限 720p"，与上表 9–10s 计费并不矛盾 —— 免费的是 **≤8 秒**。

## 2. 主表：official 官方 API

单位：积分。1 credit = $0.01。**无免费窗口，提交即扣**（`creditsCharged`）。

| 时长 | 480p | 720p Turbo（`t2v`/`i2v`/`minimax`） | 720p Base（`minimax` 质量档） |
|---|---|---|---|
| 1–4s | 不支持（下限 5s） | 不支持（下限 5s） | 不支持（下限 5s） |
| 5s | 仅 `seedance20`：51（见 §3） | 15 | 20 |
| 6s | 不可枚举 ⛔ | 18 | 24 |
| 7s | 不可枚举 ⛔ | 21 | 28 |
| 8s | 不可枚举 ⛔ | 24 | 32 |
| 9s | 不可枚举 ⛔ | 27 | 36 |
| 10s | 不可枚举 ⛔ | 30 | 40 |

- 720p 一列可用公式确认：`t2v` / `i2v` 走 **`duration × 3`** 固定公式（实测 5s = 15 积分）；
  `minimax` 720p turbo 官方定价 **$0.03/秒** ⇒ 同值。
- 720p base 官方定价 **$0.04/秒**。
- 取消任务**全额退回**（`creditsRefunded == creditsCharged`），这是 official 独有的。

## 3. 为什么 official 的 480p 列无法枚举

| 入口 | 支持 480p | 已知报价 | 能否按秒外推 |
|---|---|---|---|
| `t2v` | ❌（720p） | 15 积分/5s | — |
| `i2v` | ❌（720p） | 15 积分/5s | — |
| `minimax` | ❌（720p/1080p） | 15/20/20/25（5s 四档） | — |
| `seedance20` | ✅ | **51 积分/5s**（720 → 110） | ⛔ 官方明确按入口定价，禁止由分辨率/时长推算 |

实测反例说明为什么不能推：`t2v` 与 `seedance20 720` 的输出分辨率接近（1248×704 vs 1280×720），
但价格是 **15 vs 110**，差 7 倍多 —— 平台按 `model` 入口定价，与实际输出分辨率无关。

## 4. 两线并列：同一档位的价差只落在 ≤8 秒

| 时长 | web 720p 快速 | official 720p Turbo | 差额 |
|---|---|---|---|
| 5s | 0 | 15 | −15 |
| 6s | 0 | 18 | −18 |
| 7s | 0 | 21 | −21 |
| 8s | 0 | 24 | −24 |
| 9s | 27 | 27 | **0** |
| 10s | 30 | 30 | **0** |

**结论：进入计费区后（>8s），两条线的每秒单价完全一致（3 积分/秒）；
价差全部来自 web 侧的免费窗口。** 上一轮"web 与 API 是不是一个价"的答案在此具体化：
计费单价同，实付价不同。
